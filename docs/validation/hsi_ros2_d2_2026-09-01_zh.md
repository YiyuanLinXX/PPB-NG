# HSI ROS 2 D2 硬件验证记录（2026-09-01）

## 范围与安全边界

本轮在 HyperFusion 已确认 FX10e 与 SWIR3 均可连接之后进行。测试只覆盖单设备
`prepare -> arm -> start -> stop` 链路：加载 SpecSensor、打开指定 profile、加载工厂
标定包、应用并读回固定配置、关闭快门、关闭 handle 并卸载 SDK。最初按旧设计验证了
External；随后按机器人最终方案改为 Internal 连续 line timing 并再次验证 FX10e。

本轮没有调用 `begin_dark` 或 `start_sample`，没有开始连续采集，也没有发送外部触发；
生成的测试 session 只包含空 checkpoint，不包含图像数据。HyperFusion、eBUS Player
在测试前均已退出。

9 秒成功，未出现选择窗口，因此可以在 SSH 无桌面环境运行。

## SWIR3 结果

初始配置曾按未经本机数据确认的 `640 x 384` 推定值启动。节点正确拒绝不匹配配置，
关闭 handle 并释放 SDK。增强错误信息后，第二次连接读到真实值：

| 项目 | 实际值 |
| --- | --- |
| profile | `SWIR3 with NI` |
| sensor serial | `462111` |
| NI channel | `img0` |
| NI camera file | `Specim_SWIR3.icd` |
| geometry | `384 spatial x 288 spectral x 2 bytes` |
| frame bytes | `221184` |
| requested line rate | `20.590000 Hz` |
| applied line rate | `20.590113 Hz` |
| requested exposure | `17800.000000 us` |
| applied exposure | `17799.200058 us` |
| trigger mode | `Internal`（配置已固化；本表其余读回来自单机 D2） |
| calibration pack | loaded |
| shutter at ready point | closed，且读回确认 |

帧率与曝光的小差异来自 NI/相机时钟寄存器量化。代码采用严格且有限的容差：帧率
绝对误差不超过 `0.001 Hz`，曝光绝对误差不超过 `1 us`（同时保留很小的相对容差）。
几何、byte depth、frame bytes、trigger mode、序列号、profile 和标定包仍要求精确匹配。

## 本轮发现并修复的问题

1. Windows `.cmd` 对包含空格的 profile 长命令行参数传递不可靠，曾使 ROS 参数解析
   进程以 `0xC0000409` 退出。改为安装并使用 ROS YAML 参数文件后解决。
2. `start` 原先只返回泛化成功消息；现在返回 profile、serial、geometry、frame bytes、
   packet size 与 calibration-pack readback。
3. 配置不一致原先没有实际值；现在同时返回 requested/actual 全量关键参数。
4. SWIR 的真实几何经硬件读回确定为 `384 x 288`，对应队列上界修正为 `221184` bytes。
5. SWIR 时钟量化原先被过严的浮点比较误判；现使用有物理意义的小容差，并继续记录
   实际读回值。

## 固化配置

- 用户唯一配置：`src/ppbng_bringup/config/ppbng_config.yaml`

统一配置由 CMake 安装到 `install/ppbng_bringup/share/ppbng_bringup/config/`。不得用长串
命令行参数替代配置文件，尤其不要在 `.cmd` 层直接传递带空格的 profile 名。
